Seeing Together

The glasses saw it. The robot should still know where.

Shared, time-stamped object memory for a person in RayNeo X3 Pro glasses and a Unitree Go2.

Khang Nguyen and Hyun Kyum Kim · UCLA ECE M202A, Fall 2026

17 named places on one lidar map.Checkpoint slides: P01_Checkpoint.pdf (November 10, 2026)

Checkpoint slides

Question

Can shared memory beat a robot that only remembers itself?

Can a robot improve object-search success and efficiency by maintaining shared, time-aware object-centric memory from human smart glasses and robot observations, and actively deciding when to inspect, ask, or report?

Instead of a language instruction or a long video log, the robot keeps object-level evidence and decides what to acquire next. A person may see a screwdriver on the workbench while the dog is elsewhere. Later the workbench is empty. Both observations stay. The earlier one may be stale. The robot then looks again, or asks.

Minimum deliverable. The Go2 reaches an object that the glasses saw being moved while it was out of the robot’s view.

Scope

One lab, one wearer, a small set of objects.

The setting is one indoor lab, the RayNeo X3 Pro, a laptop hub, and the Go2 with ROS 2. AprilTags at known positions in the Go2 map are the shared anchor.

In scope

What we build

  • A small predefined set of everyday objects, chosen so detection and localization are reliable.
  • The robot explores first, builds the map and an object-location memory, and initializes the shared memory.
  • The glasses stream camera and IMU. Tags place the wearer. Object moves update location and time before anyone asks.
  • An agent reads that memory and sends navigation goals to the Go2.

Out of scope

What we leave out

  • Open-vocabulary detection of arbitrary objects.
  • Localization without tags. No visual SLAM on the glasses.
  • Multiple rooms, multiple users, or outdoor use.

How it works

One lab. Three streams.

The glasses do not run SLAM. Tags at known positions in the Go2 map are the link between the two.

01

Glasses

The RayNeo X3 Pro streams camera frames and IMU to the laptop. A tag in view places the wearer. An object move updates that object’s location and time.

02

Memory

The laptop keeps object-level evidence, not a long video log. Each observation has a place and a timestamp, so a later look can mark an earlier one stale.

03

Go2

The dog builds the map and the first object memory. An agent reads that memory and sends a navigation goal. The planner, not the model, routes around furniture.

Lab map

The dog maps the room, then walks the names.

The robot reads one occupancy grid, about 100 m², saved 21 Nov 2026. People marked 17 places on it: desks, the sofa, the podium, the doors, the water cooler.

Tag pose

Two tags, not one, where the view is hard.

After calibration (640×480, RMS 0.27 px), the glasses estimate their pose from 15 cm AprilTags and we compare with tape. Under 1 m both setups stay within a few centimeters. Head-on at 2–3 m, one tag flips the tilt.

Saved places

The robot already has a name for where to stand.

Each place is a stand pose, a facing direction, and a photo from the Go2’s front camera. The agent chooses the name. The planner drives there.

Evaluation

Same object, three memories.

An object from a small predefined set is moved while the robot is not looking. Then the robot is asked to find it. At least 10 trials per condition, same placements.

ConditionWhat the robot uses
Robot-onlyOnly its own last observation of the object.
Naive human + robotGlasses observations, without timestamps or staleness.
Seeing TogetherShared, time-stamped memory from the glasses and the robot.
  • Primary metric: task success rate. Secondary: search time, unnecessary actions, clarification turns, and final position error.
  • Trials: at least 10 per condition, with the same object placements across conditions.
  • Stress tests: the object is moved out of the robot’s view, and Wi-Fi drops in the middle of a task.
  • Component test: tag pose in a home test room, at 0.5, 1, 2, and 3 m and at 0°, 30°, and 60°, one tag against two.

Response to checkpoint feedback

  • Which objects are recorded before the user asks? A predefined set. The robot builds the initial memory. The glasses update a tracked object when it moves.
  • Compare one tag with two. Added to the pose test. Two tags cut the hardest errors, from 120 cm to 6 cm at 2 m / 30°, and from 17 cm to 5.5 cm at 1 m head-on. We will place at least two tags per area.
  • Validate in a home test room first? The instructor approved it. Tag pose runs there against tape. The lab is for the end-to-end comparison.

Remaining risks

Where it can still fail, and the fallback.

RiskFallback
Tag pose error is too large to place an observation on the map. It is small up to 1 m, but a head-on view at 2–3 m flips the tilt.Two or more tags per area, and oblique views. Resolve the tilt with the IMU gravity direction. Otherwise snap the observation to the nearest saved place.
Live tag detection is unreliable at distance while worn. In the Nov 2 live test, 15 cm tags were found in 18–93% of frames at 2 m, and in 95–100% up to 3 m with the glasses held still.Larger tags, more tags per area, or closer viewing distances.
The robot side is only tested offline on a saved map so far.Run the comparison with the robot driven to the saved places.
Wi-Fi drops during a task.Buffer observations and resume. The IMU stream already recovers after a drop.
